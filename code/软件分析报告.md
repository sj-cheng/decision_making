## 1. 程序怎么跑起来

现有栈不在本机 `~/catkin_ws` 里直接 `roslaunch`。每个功能是一个 Docker 容器，`--net host`，并把 `/dev` 和 `/nfs` 挂进去。容器之间用主机 ROS master 通信。

较新的总启动脚本是 `/nfs/start_tree.sh`（2026-10-09）。它开一个 tmux，六个窗格按顺序拉起：

| 顺序 | 脚本 | 容器名 | 镜像 | 作用 |
|---|---|---|---|---|
| 1 | `/nfs/start_base.sh` | `tmp_env` | `192.168.30.254/library/rsg_control:latest` | 串口控制：底盘、云台、裁判 |
| 2 | `/nfs/start_localization.sh` | `localization` | `rsg_localization:latest` | MID-360 + faster-lio + 坐标变换 |
| 3 | `/nfs/start_planning.sh` | `pl_cont` | `rsg_planning` | 规划，速度发给 `/control/cmd_vel_acc` |
| 4 | `/nfs/CGY/team_policy_opti_decision/launch/start_armor_shooting_patched.sh` | `as_cont` | `rsg_armor_shooting:latest` | 海康取流、检测、云台指令 |

| 6 | `roslaunch rosbridge_server rosbridge_websocket.launch` | 无 | 本机 ROS | WebSocket，给外部界面 |

## 3. 底盘、云台、裁判

### 3.1 进程入口

文件：`/nfs/CGY/test_rsg_control/src/rsg_control_src/src/rsg_control_node.cpp`

1. `ros::init(..., "rsg_control_node")`
2. 从参数服务器读 `serial_port` 和 `load_module`
3. `roborts_sdk::Handle(serial_port)`，波特率在 `handle.cpp` 里固定为 **921600**
4. `Init()` 失败则进程返回 1
5. 按配置加载 `chassis`、`gimbal`、`referee_system`
6. 构造 `MotionCtrl`，主循环里 SDK `Spin()` 加 `ros::spinOnce()`，然后睡 1 ms

参数文件 `config/base.yaml`：

```yaml
serial_port : "/dev/serial_sdk"
load_module : [ "chassis", "gimbal", "referee_system" ]
```

udev 把 STM32 固定成 `/dev/serial_sdk`。规则在 `/etc/udev/rules.d/roborts.rules`。

`MotionCtrl` 的节点句柄是 `ros::NodeHandle ros_nh_("control")`。所以指令和状态在 `/control` 下。底盘模块自己的 `ros::NodeHandle ros_nh_` 是默认全局句柄，因此里程计话题是 `/odom`，不在 `/control` 下。

### 3.2 发给底盘的速度

订阅在 `motion_ctrl.cpp` 的 `ROS_Init()`。

| 话题 | 类型 | 写入的内部变量 |
|---|---|---|
| `/control/cmd_vel` | `geometry_msgs/Twist` | `chassis_cmd_vx_m = linear.x`，`vy = linear.y`，`vw_deg = angular.z * 180/π` |
| `/control/cmd_vel_acc` | `rsg_msgs/TwistAccel` | 只读 `twist`，同样写上面三个变量。`accel` 被忽略 |
| `/control/cmd_vel_aux` | `geometry_msgs/Twist` | 写 `chassis_aux_cmd_*`，后面加到主速度上 |

限幅在回调里做完，常量在 `include/hardware_config.h`：

| 内部量 | 限幅 | ROS 侧对应 |
|---|---|---|
| `vx`、`vy` | ±1.5 m/s | `linear.x`、`linear.y` |
| `vw` | ±300 °/s | `angular.z` 约 ±5.24 rad/s |

超时在 `MotionCtrlTimerCallback`，周期 20 ms：

```text
超过 1 秒没有新的 cmd_vel 或 cmd_vel_acc → 主速度清零
超过 1 秒没有 cmd_vel_aux → 辅助速度清零
```

注释写“500 ms”，判断条件是 `>= 1` 秒。速度指令必须持续发。

50 Hz 定时器里还会把这些量加在一起，再交给 `Chassis::ChassisSpeedCtrl`：

```text
vx = 主 vx + aux vx + 遥控通道
vy = 主 vy + aux vy + 遥控通道
vw = 主 vw + aux vw + 遥控 + 云台协调 PID + 摇摆 + 车头跟随
```

默认协调模式是底盘主动（`COORD_CTRL_CHASSIS_ACTIVE`）。这个模式下云台 yaw 会被协调控制器往车体方向拉，遥控对云台的 yaw 增量被清掉。要让云台独立转、底盘去跟云台，需要把 `/control/parameter/coord_mode/set` 设成云台主动。

`ChassisSpeedCtrl`（`chassis.cpp`）换成固件单位后经 SDK 发走：

```text
vx_firmware = vx_m * 1000      # mm/s
vy_firmware = vy_m * 1000
vw_firmware = vw_deg * 10      # 0.1 °/s
```

底盘模块每 300 ms 发一次心跳，否则固件会认为工控机离线。

现有规划不是发 `/control/cmd_vel`。`/nfs/HJT/planning_ws/.../launch/include/run_a_car.xml` 把 `cmd_vel_acc` remap 到 `/control/cmd_vel_acc`。两条话题写的是同一组变量，自己的程序发 `/control/cmd_vel` 即可，不必再包一层加速度。

### 3.3 云台指令

`rsg_msgs/GimbalAngle.msg` 的注释是：

```text
float64 pitch   # pitch 绝对角度
float64 yaw     # yaw 增量角度
```

`/control/cmd_gimbal_angle` 的回调和注释不一致。装甲程序走的是这条回调，yaw 被当成角速度：

```text
pitch_deg = msg.pitch * 180/π     # 绝对角
yaw_rate  = msg.yaw   * 180/π     # 度/秒，限幅 ±960
```

另外三条才是注释字面上的含义：

| 话题 | 类型 | 代码里的含义 |
|---|---|---|
| `/control/cmd_gimbal_pitch_angle` | `std_msgs/Float64` | pitch 绝对角，弧度，再乘 `180/π` |
| `/control/cmd_gimbal_yaw_angle` | `std_msgs/Float64` | yaw 增量角，弧度，再乘 `180/π`，限幅 ±90° |
| `/control/cmd_gimbal_yaw_rate` | `std_msgs/Float64` | yaw 角速度，弧度/秒，再乘 `180/π`，限幅 ±960 °/s |
| `/control/cmd_gimbal_yaw_angle_aux` | `std_msgs/Float64` | 另一路 yaw 增量，弧度 |

云台下发周期也是 20 ms。角度进固件前再乘 10，单位变成 0.1°。

装甲识别发布云台指令的函数在镜像内 `ros_if/ros_if.py`：

```text
publish_gimbal_angle(pitch_abs, yaw_rate)
话题 /control/cmd_gimbal_angle
msg.pitch = pitch_abs    # 弧度
msg.yaw   = yaw_rate     # 弧度/秒
```

### 3.4 状态反馈

`MotionCtrl` 以 20 Hz 发布（`ROS_INFO_PUB_TIMER_PEROD = 0.05`）：

| 话题 | 类型 | 内容 |
|---|---|---|
| `/control/chassis_info` | `rsg_msgs/ChassisInfo` | 底盘在线、四电机在线、目标 vx/vy/vw、yaw、yaw_rate、电池百分比和电压 |
| `/control/gimbal_info` | `rsg_msgs/GimbalInfo` | 云台在线、yaw/pitch 电机在线、编码器角、陀螺仪角、角速度、目标角。角度单位是度 |
| `/control/shoot_info` | `rsg_msgs/ShootInfo` | 拨弹在线、摩擦轮、射频、射速、已发弹数 |
| `/control/rc_info` | `rsg_msgs/RCInfo` | 遥控 |
| `/control/referee_info` | `rsg_msgs/RefereeInfo` | 见下 |
| `/control/motion_ctrl_info` | `rsg_msgs/MotionCtrlInfo` | 控制器内部状态 |
| `/control/virt_odom` | `nav_msgs/Odometry` | 虚拟里程计 |

`/odom` 由底盘串口回调直接发，不经过这 20 Hz 定时器。`frame_id=odom`，`child_frame_id=base_link`。同时发 TF `odom → base_link`。位置来自固件的毫米值除以 1000。这是编码器里程计，会漂，规划不使用它。

在线判断：

```text
底盘：2 秒内收到过底盘包
云台：0.5 秒内收到过云台包
遥控：底盘在线且固件报告 aux_rc_online
```

云台 TF 在 `GimbalInfoCallback` 里发：

```text
base_link → gimbal
translation = (0, 0, 0.15)
rotation    = yaw_ecd，pitch 固定为 0
```

pitch 变化不会出现在 TF 里。

### 3.6 服务和动作

都挂在命名空间 `control` 下。装甲程序实际调用的是：

| 名称 | 类型 | 作用 |
|---|---|---|
| `/control/parameter/fric_enabled/set` | `rsg_msgs/SetBool` | 摩擦轮 |
| `/control/parameter/gimbal_yaw_ctrl_mode/set` | `rsg_msgs/SetGimbalYawCtrlMode` | 装甲侧把它设成角速度模式 |
| `/control/parameter/gimbal_yaw_ctrl_mode/get` | 对应 Get 服务 | |

| `/control/ShootAsync` | `actionlib`，`rsg_msgs/ShootAsyncAction` | 按发数射击 |
| `/control/parameter/coord_mode/set` | `rsg_msgs/SetCoordMode` | 底盘主动 / 云台主动 |

|---|---|---|
| `xfer_format` | `1` | `kLivoxCustomMsg`。`/livox/lidar` 是 `livox_ros_driver2/CustomMsg` |

### 4.3 faster-lio

`faster_lio/config/avia.yaml`：

```yaml
common:
  lid_topic: "/livox/lidar"
  imu_topic: "/livox/imu"
  time_sync_en: true
preprocess:
  lidar_type: 1          # Livox
```

### 4.4 变到场地坐标

文件：`coordinate_change/src/multi_vehicle_localization_yaml.cpp`

订阅 `/Odometry`，发布 `/robot_pose`（`nav_msgs/Odometry`，队列 10）。

雷达到云台的外参写死在 `define_lidar2gimbal()`：

```text
平移 (0, 0, 0.46) 米
旋转
  1  0  0
  0 -1  0
  0  0 -1
```

也就是雷达在云台坐标系上方 0.46 m，并绕 X 轴转 180°。雷达如果改了安装，改这里，不要只改 JSON 里那个全 0 的外参。JSON 那组是驱动输出坐标系，定位没用它。

坐标变换顺序（代码注释）：

```text
T_G_L  = define_lidar2gimbal()
T_B_G  = TF：gimbal ← base_link
T_B_W1 = T_L_W1 * T_G_L * T_B_G
T_B_W0 = T_W1_W0 * T_B_W1
```

`initial_fixed=true` 时，`T_W0_M` 来自 `config/vehicle_initial_poses.yaml` 里键 `blue1`：

```yaml
blue1:
  position: [17.6, 9.2, 0.1]
  rotation: rotation0     # diag(-1, -1, 1)
```

然后发布 TF `map → world`，以及 `/robot_pose`：`base_link` 在 `map` 下的位姿。规划的 `rsg_planning.launch` 订阅的就是这个话题（参数名 `odom_topic`，值 `robot_pose`）。

TF 帧名默认：

```text
/listen/tf_gimbal_frame    = /gimbal
/listen/tf_base_link_frame = /base_link
```

定位节点启动后会等 `base_link` 和 `gimbal` 的 TF，最长 3 秒。控制节点没起来时，这里会报 TF 异常，位姿会是单位阵附近的错误值。所以 `start_tree.sh` 里定位比底盘晚 8 秒。

### 4.5 自己用雷达时

- 只要车在场地里的位姿：订阅 `/robot_pose`。
- 要原始 Livox 点：订阅 `/livox/lidar`（CustomMsg）或 `/livox/points`。
- 不要再起第二个 `livox_ros_driver2`。命令端口和点云端口只能有一个进程绑。

### 5.2 打开和取图

`HikMVCamera.openCamera()`：

1. `MV_CC_GetSDKVersion()`
2. `MV_CC_EnumDevices(MV_GIGE_DEVICE | MV_USB_DEVICE)`
3. 设备数为 0 则抛 `CameraNotFound`
4. 打印每台的型号和序列号，然后固定使用下标 **0**
5. `MV_CC_CreateHandle` + `MV_CC_OpenDevice(MV_ACCESS_Exclusive, 0)`
6. `TriggerMode = Off`（自由采集，不是外触发）
7. 读 `PayloadSize`
8. `MV_CC_StartGrabbing()`

代码里没有设置曝光、增益、白平衡、分辨率。这些用相机里已经保存的参数。`setCameraWB()` 整段被注释掉了。

`getImage()`：

1. `MV_CC_GetImageBuffer(..., 1000)`，超时 1 秒，失败抛 `NoImageError`
2. 按像素类型分支。彩色转 `PixelType_Gvsp_BGR8_Packed`，黑白转 `Mono8`
3. `MV_CC_ConvertPixelType`
4. 彩色图变成 `numpy.uint8`，形状 `(height, width, 3)`，BGR
5. `MV_CC_FreeImageBuffer`

`ImageCapture.getImage()` 返回 `(image, time.time())`。时间戳是取完图之后的主机时间，不是相机硬件时间戳。

### 5.3 图像不进 ROS

`pipeline.py` 里 `CaptureWorker`：

```text
capture = ImageCapture(use_virt_cam=False)
capture.init()
while capture_loop_on:
    timestamp = capture.getImageToBuffer(np_image)
    stamped_image = StampedImage(captureImgPreproc(np_image), timestamp)
```

这是多进程里的内存缓冲，后面直接进检测。没有 `sensor_msgs/Image` 发布者。

### 5.4 独占

`MV_ACCESS_Exclusive` 意味着装甲容器活着时，第二个进程再 `OpenDevice` 会失败。要自己拿图像：

1. 停掉容器 `as_cont`，按 `hik_camera.py` 的顺序打开，使用 BGR `numpy`；或
2. 改 `CaptureWorker`，把 `np_image` 发布成 `sensor_msgs/Image`（`bgr8`），其他节点再订阅。

不要两路同时打开同一台相机。

相机相对云台的外参见第 3.7 节。检测代码通过 TF 把像素目标和 `gimbal`、`camera` 对上。pitch 不在 `base_link → gimbal` 的 TF 里，只在 `/control/gimbal_info` 的 `pitch_angle_ecd` / `pitch_angle_gyro`（单位度）里。

补丁 `patched_pipeline.py` 额外订阅：

```text
/control/gimbal_info
/control/referee_info
```

用云台反馈做瞄和射击门控。它把 `publish_gimbal_angle` 包了一层，退出时保持最后姿态，而不是把云台角清零。

## 6. 坐标系汇总

```text
map
 └─ world
     └─ odom
         └─ base_link
             └─ gimbal          z = 0.15 m，仅 yaw
                 └─ camera      x = 0.1 m，yaw=-90°，roll=-90°

livox_frame  --(代码外参 z=0.46, Rx=180°)-->  gimbal
```

| 话题 | 坐标系含义 |
|---|---|
| `/odom` | 单片机里程计，`odom` 下的 `base_link`，会漂 |
| `/Odometry` | faster-lio 局部世界系下的雷达位姿 |
| `/robot_pose` | 场地 `map` 下的 `base_link`。导航用这个 |
| `/control/cmd_vel` | 车体前后左右和自旋。默认底盘主动时，云台会被拉回车体朝向 |

## 7. 适配时的最小接口

只开车、用定位、暂时不用这台相机：

```text
发布  /control/cmd_vel          geometry_msgs/Twist
      linear.x/y 米/秒，angular.z 弧度/秒
      持续发布，间隔不要超过 1 秒
订阅  /robot_pose               nav_msgs/Odometry
订阅  /control/chassis_info     电机和电池
订阅  /control/referee_info     比赛和血量
```

要转云台：

```text
服务  /control/parameter/gimbal_yaw_ctrl_mode/set
      设为 GIMBAL_YAW_CTRL_MODE_RATE
发布  /control/cmd_gimbal_angle
      pitch：绝对角，弧度
      yaw：角速度，弧度/秒
同时看 /control/gimbal_info 的角度反馈（度）
如果云台被底盘协调拉回去，再设 coord_mode
```

要自己的检测用这台海康：

```text
停掉 as_cont
按 hik_camera.py：
  枚举 USB → 打开第 0 台 Exclusive → TriggerMode Off → StartGrabbing
  GetImageBuffer → 转 BGR8 → numpy (H, W, 3)
外参用 TF gimbal → camera，不要假设 /dev/video0
```

要自己的点云算法：

```text
订阅 /livox/lidar     livox_ros_driver2/CustomMsg
或    /livox/points   转好的点云
订阅 /livox/imu       sensor_msgs/Imu
不要再绑定 192.168.1.50 的 56101/56301/56401
```
